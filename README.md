# PushSaaS — платформа веб-пушей (Next.js + Supabase)

SaaS для отправки веб-push уведомлений (работают на **Android и iPhone iOS 16.4+** через один стандарт Web Push / VAPID). Архитектура ролей и биллинга портирована из проекта **TryVice**.

## Стек

- **Next.js** (App Router) — админка + API-роуты
- **Tailwind CSS v4** + собственный UI-kit в `app/ui/` (Button, Input, Textarea, Select, Badge, Card, Checkbox, Toggle, Dialogs) — дизайн-токены свет/тьма через CSS-переменные; браузерные `confirm/alert/prompt` заменены на модалки/тосты (`useDialogs`)
- **Supabase** (Postgres + Auth + RLS) — БД, авторизация, права
- **web-push** ([github.com/web-push-libs/web-push](https://github.com/web-push-libs/web-push)) — отправка пушей
- **CloudPayments** — приём оплаты, рекуррентные токены
- Деплой: Vercel (админка + крон) — бесплатный тариф достаточен для старта

## Модель тарификации

Списывается **1 единица за каждый отправленный push** (рассылка на 1000 подписчиков = 1000).
Два баланса на проекте (как «примерки» в TryVice):

| Баланс | Поведение |
|---|---|
| `tariff_pushes_remaining` | Выдаётся на период, **сгорает** при блокировке/продлении. Тратится первым |
| `package_pushes_remaining` | Разовые докупки/бонусы, **не сгорают**. Тратятся вторым |

### V2-пакет (2026-07)

**Фиксы:**
- `subscribers.paused` — отдельный от `is_active` флаг: приостановка по просьбе владельца больше не путается с «устройство отвалилось (410)». UI различает три статуса.
- Отложенный welcome (`automations.delay_minutes` теперь реально соблюдается — уходит через ту же очередь `automation_jobs`, что и событийные автоматизации).
- Rate limiting на `/api/public/subscribe` и `/api/public/event` (таблица `rate_limit_hits`, тот же паттерн, что у `otp_requests`).
- `run-automations` дренирует несколько батчей за один вызов крона (до 5×300, бюджет времени 45с), не только 300 за тик.
- **Защита от рассинхрона миграций:** все новые колонки (`paused`, `attribution_*`, `campaigns.actions`, `resend_api_key`) читаются/пишутся best-effort в изолированных запросах — если 0009 ещё не накатана, платформа не падает, просто новые фичи выключены.

**Новое:**
- **Rich push** — до 2 кнопок-действий (`campaigns.actions`, `automations.config.actions`) в конструкторе рассылки, `/api/v1/campaigns`, `/api/v1/trigger`; обрабатываются в `service-worker.js`.
- **Email-канал OTP** — Resend API, только для возвратных клиентов (email подтягивается автоматически из `client.email` в транзакционных вебхуках заказа рядом с телефоном). Каскад: push → email → Telegram → SMS.
- **Таргетинг по email** — `/api/v1/campaigns` принимает `emails`/`email` наравне с `phones`/`phone` (`lib/identity.ts: emailsToSubscriberIds`).
- **Универсальный триггер — транзакционные vs рассылочные** — тоггл в конструкторе автоматизации: транзакционная шлёт точечно по телефону (нет телефона → пропуск), рассылочная — по сегменту/всем (сегмент тоже из тела по пути).
- **Атрибуция заказов к пушам** (`order_attributions`, `/api/v1/attribute`) — last-click модель: скрипт трекинга помечает клик по пушу first-party-кукой (`document.cookie` в виджете, формат `<campaignId>.<timestampMs>`), отдельный вебхук на заказ сверяет куку и записывает выручку к кампании. Настройки — блок на странице «Кампании»: только имя куки (по умолчанию `pss_attr`), путь в теле заказа больше не настраивается руками — InSales сам кладёт любую куку из списка `/admin2/checkout` → «Список cookies, которые требуется сохранить при оформлении заказа» в `order.cookies.<имя>`, и мы читаем её ровно оттуда (подтверждено реальным телом заказа InSales, `number`/`total_price` — дефолтные пути к номеру/сумме тоже подтверждены). Мерчанту нужно вписать одно и то же имя куки в двух местах — у нас и в `/admin2/checkout`.
- **Расширенная аналитика** (`/admin/projects/[id]/analytics`) — рост подписчиков за 30 дней, разбивка по платформам, топ кампаний по CTR, активность автоматизаций, выручка (если атрибуция включена).
- **Экспорт/импорт подписчиков** (`/api/admin/subscribers/export|import`) — CSV с любыми накопленными `attributes`; импорт обогащает профиль по выбранному ключу (телефон или свой атрибут).
- **Быстрый поиск** на странице «Подписчики» + починено сохранение тегов (шло через RLS-клиент без реального health-check; переведено на серверный роут с явной обработкой ошибок).
- Каскад OTP: лейблы + поля друг под другом вместо сетки.

⚠️ Применить `supabase/migrations/0009_v2.sql`. Для атрибуции — включить на странице «Кампании», указать имя куки и вписать то же имя в InSales `/admin2/checkout`; путь в теле заказа определяется автоматически.

### Вход по телефону — доработка (2026-07, миграция `0010_identify_haskimail.sql`)

- **Email-канал переведён на [Haskimail](https://haskimail.ru/email-api)** (было — прототип на Resend, никогда не был подключён у реальных клиентов, заменён без миграции данных). Ключ — `project_secrets.haskimail_server_token`, настраивается в проекте самостоятельно, как SMS/Telegram.
- **Порядок каскада настраивается** — стрелки вверх/вниз в «Вход по телефону»; хранится в `oidc_clients.config.channel_order`, отсутствующие каналы всегда достраиваются в конец дефолтного порядка (`lib/otp/index.ts: resolveOrder`).
- **Канал нельзя включить тогглом без сохранённого ключа** — блокировка и в UI (тоггл `disabled`), и на сервере (`/api/admin/oidc/settings` тихо сбрасывает `channels.X=true`, если ключа для X нет — защита от прямых запросов в обход формы).
- **Подтверждение владения телефоном — опционально** (`oidc_clients.config.require_phone_verification`, **дефолт `true`/обязательно** — безопасный дефолт). Тоггл в UI с явным предупреждением о риске угона аккаунта при выключении.
- **`/api/public/identify`** (новый публичный эндпоинт, тоггл-gated) — привязывает push-устройство к телефону/почте БЕЗ кода, доверяя авторизованной сессии магазина. Вызывается темой InSales через `window.PushSaaS.identify({phone,email,name})` после `ajaxAPI.shop.client.get()` — готовый сниппет показан в UI (только когда тоггл выключен). Комбинация `PushSaaS.subscribe()` + `PushSaaS.identify(...)` = кнопка «Подписаться»/«Обновить данные» для уже авторизованных в InSales клиентов.
- Аудит: `identities.verification_source` (`'otp'` | `'insales_session'`) — не влияет на логику, только для поддержки/отладки.
- **Скрытие кнопки «Войти через PushSaaS»** (`/api/public/login-visibility`, вызывается из виджета on-load) — если тоггл выключен (обязательное подтверждение), кнопка всегда показана: код при входе уйдёт другим каналом, а привязка дозаписывается через `identify()`. Если тоггл включён и push — единственный способ входа, кнопку скрываем, пока у устройства нет ни одной привязки в `identity_devices` (иначе пользователь видит кнопку входа, которая гарантированно откажет). Виджет ищет нативный блок InSales по селектору `.co-login--social_login`.
- **PushSaaS.identify() как безусловный дослав данных при подписке** — виджет уже вызывает `identify()` сразу после `subscribe()` и повторно при каждой загрузке страницы для уже подписанных, так что привязка телефон+устройство появляется сама по мере того, как авторизованный в InSales клиент просто пользуется сайтом — отдельного флоу «подпишись, чтобы привязать» не потребовалось.

⚠️ Применить `0010_identify_haskimail.sql`. Проверено live: дефолт (`require_phone_verification` не задан) блокирует `/api/public/identify` (403 `verification_required`); при включённом тогле — реальная привязка устройства к телефону/почте подтверждена в БД.

## Ключевые архитектурные правила (из TryVice)

- **4 уровня защиты:** UI (не граница) → middleware (граница) → RLS (граница) → API-роуты проверяют себя сами.
- `is_admin()` — `SECURITY DEFINER`, единственный источник правды о роли, обходит рекурсию RLS.
- Все мутации баланса — только `service_role`, **кроме** супер­админских RPC (`admin_activate_tariff`, `admin_grant_bonus`) и `unsubscribe_project`, которые сами проверяют `is_admin()`/владение и выданы `authenticated`.
- `owner_id` заморожен триггером после создания.
- Приватный VAPID-ключ и токен карты — в `project_secrets`, клиенту не видны (только `service_role`/admin).
- **SaaS-нюанс:** service worker подписчика обязан лежать в корне домена КЛИЕНТА — поэтому модуль онбординга выдаёт файл + сниппет, клиент кладёт к себе (у нас проверено на yuliawave.com ✅).
